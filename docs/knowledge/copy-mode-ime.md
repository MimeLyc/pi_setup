# Copy-mode IME integration facts

- Final `controller.ts:kick()` recovery is gated by `restoreRequired || forcedSources.size > 0`; `reconcile()` does not apply exit policies to an interval with no entered phase or possible forced state. Every restore candidate is tracked before selection, and targetless/keep disabled cleanup avoids a query.

- `@luan.sh/pi-copy-mode` 0.3.4 exports no input source lifecycle API. `src/config/settings.ts` exposes reactions and copy-on-select settings only.
- Upstream `src/runtime/copy-mode.ts:createCopyModeHost()` registers screen decorator `pi-copy-mode.active` in `enter()`. `exit()` removes it for copy, cancel, surface loss, and disposal. `requestSelectionAction()` temporarily removes modal input while awaiting a comment/reaction; the decorator remains registered.
- Upstream `src/annotations/ui/composer-overlays.ts:showCommentOverlay()` mounts `pi-copy-mode.annotations.comment-editor`. `pi-libtui/src/overlay/modal-mount.ts` registers the region and disposes it for every dialog result, including save, cancel, and delete. Keyboard comments, mouse comments, and annotation pill editing use this overlay.
- The bundled libtui registry publishes `Symbol.for("pi-libtui/mouse/registry/v1")`, protocol of the same string, version `1`. Its `registry-state/v1` symbol stores registration arrays. Registration removers close over the exact object identity.
- `extensions/copy-mode-ime/registry.ts` observes publication and wraps registration methods. It reads existing state to reject unsafe late attachment, and restores only descriptors it still owns. No upstream imports or storage mutation are required.
- `extensions/copy-mode-ime/controller.ts:ImeController` serializes queries and selections, coalesces state changes, checks revisions after writing queries, and retains a restoration obligation before attempting selection. `CopyInterval.entrySource` is the first safe query result after older interval cleanup; comment captures update `writingSource` separately. `generation` distinguishes exit/re-entry even when state changes coalesce during an in-flight CLI call.
- `controller.ts:applyPolicy()` handles fixed source IDs, `restore-entry`, `restore-writing`, and `keep`. `exhaustedRestoreSources` prevents immediate recovery from repeating failed recorded/fallback targets while allowing a distinct exit/shutdown target. `forcedSources` lets later disabled-state cleanup recognize automatically selected sources; `finish()` compares them against the primary target and uses fallback as expected only when that primary is absent. `finish()` caches disposal and drains all tasks re-started from `finally()`.
- `controller.ts:kick()` uses `sessionShutdown` recovery once a closed controller still owns an interval and computes manual-restoration guidance after recovery settles. Standalone comment entry re-checks `closed` after its asynchronous writing query, so it cannot start selection during shutdown.
- `extensions/copy-mode-ime/config.ts:readConfig()` reads `PI_COPY_MODE_IME_CONFIG_FILE` only at TUI session start through `index.ts`. The file requires `hooks`; omitted hook keys inherit navigation/environment and writing-restoration defaults. Reads stop at 16385 bytes, reject non-regular files without blocking on FIFOs, and sanitize I/O, parse, and schema errors. Relative paths use the current working directory; `~/` uses `os.homedir()` and repeated slashes after the tilde are normalized before resolution. `backend.ts` preserves the `readConfig`/`ImeConfig` exports.
- Both macOS CLIs query with no arguments and select with one source ID. macism can print an error and exit zero for an unavailable source, so `backend.ts` reads back every selection. macism discovery falls back to im-select only on ENOENT.
- Pi 1.5.2 emits and awaits `session_shutdown` in extension load order before reload, replacement, and graceful exit; the replacement instance receives `session_start`. Upstream host disposal can remove the copy-mode decorator before the companion's shutdown handler. If that `copyModeExit` completes the interval, a later `sessionShutdown` hook does not reopen it; matching both policies avoids load-order-dependent teardown results. `ctx.mode === "tui"` is required because RPC also has `hasUI === true`.
- `backend.ts:run()` classifies Node execFile failures by operation and CLI label. Output-limit errors take precedence over the killed flag, followed by deadline kills, external signals, and exit/error codes; raw stdout/stderr and input source arguments are excluded from warnings.
- The initial scaffold enabled `checkJs` and `strict` without typing `FORBIDDEN_FILE_PATTERNS` callbacks in `scripts/check-hygiene.mjs`; an array JSDoc annotation resolves the five pre-existing implicit-any errors without changing scanning behavior.
